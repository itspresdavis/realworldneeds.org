# Institutional-Grade Audit Matrix

## Protected baselines

The current RWN brand, logo treatment, green-and-ink color system, light finder surface, detailed Three.js globe, deep zoom, marker behavior, WebGL fallback, and page-scroll ownership are **protected baselines**. This pass may improve their clarity, resilience, performance, accessibility, or maintenance boundaries; it must not replace them with a new identity or a generic visual system.

## Evaluation matrix

| Surface | Primary public job | Required evidence | High-risk failure to avoid |
| --- | --- | --- | --- |
| Homepage finder | Move a person from an essential need to credible services | Search, category, location, mobile, keyboard, and no-result paths | Making globe exploration a prerequisite to help |
| Globe | Offer geographic context and visual discovery | Wheel/touch/keyboard behavior, fallback, deep zoom, resize, reduced motion | Interfering with ordinary page scroll or hiding text discovery |
| Directory and search | Help people scan and refine a large, uneven catalog | Relevance corpus, result hierarchy, zero-result recovery, low-bandwidth behavior | Pretending category coverage is equally mature everywhere |
| Service page | Enable a stranger arriving from search to contact or navigate safely | Source, review date, access note, call/directions, related alternative, print | Overstating availability, hours, eligibility, or RWN authority |
| Trust and public policies | Explain RWN’s role and allow accountable correction | Source/provenance, privacy, accessibility, correction/contact pathways | Fabricating organizational facts, partners, contacts, or legal assurances |
| Offline and location | Improve resilience without collecting more than needed | Permission denied, timeout, cached state, reconnect, unsupported device | Trapping users behind permission or implying precision not supported by data |
| SEO and technical delivery | Make useful pages discoverable, stable, and fast | Metadata, structured data, internal links, canonical/sitemap, build and browser QA | Programmatic pages that repeat weak or misleading claims |

## Legal-content implementation boundary

This pass can make public disclosures clearer, reduce overclaiming, expose existing policy routes, and implement security/privacy/accessibility mechanics supported by the repository. It cannot establish legal sufficiency for a particular jurisdiction, invent a monitored contact channel, certify regulatory compliance, or substitute for an attorney’s review of final legal notices. Counsel-dependent items will be separated in the release report rather than presented as complete.

## Release standard

Every implemented change needs source or browser evidence, must retain the current brand and globe experience, and must pass the existing build, data, globe, directory, browser, offline, and production deployment gates. Any unresolved high-impact issue is documented with a specific safe next architecture rather than silently deferred.
